## 전체 요약

현재 프로젝트는 기존 온라인 카드 쇼핑몰 구조 위에 수동 상품(`MANUAL_PRODUCT`)을 추가하고, 이를 검색, 장바구니, 체크아웃, 주문, 관리자 화면까지 연결하는 작업이 진행 중이다.

주요 방향은 다음과 같다.

- 기존 `UNION_PRICE` 카드 상품 중심 구조를 `MANUAL_PRODUCT`까지 처리할 수 있는 멀티 상품 테이블 구조로 확장
- 체크아웃 확정 로직을 상품 테이블별 핸들러(`CheckoutLineHandler`) 구조로 리팩터링
- 관리자 주문 목록/상세 API 및 관리자 주문 화면 추가
- 수동 상품 등록, 검색 맵 동기화, 장바구니/체크아웃 연동 기반 추가
- 인증 응답 구조를 `user` 객체 중심으로 정리
- 프론트 API 에러 메시지 i18n 처리 보강

현재 diff 기준으로 추적 파일만 약 63개 파일, `+1119 / -585` 줄 규모의 변경이 있으며, 여기에 신규 DTO, 서비스, 컨트롤러, 체크아웃 핸들러, 수동 상품 관련 파일들이 추가되어 있다.

## 백엔드 현황

### 체크아웃

체크아웃 확정 로직은 가장 큰 구조 변경이 완료된 상태다. `CheckoutConfirmServiceImpl`이 카드 상품 전용 검증과 재고 차감 로직을 직접 처리하던 구조에서 벗어나, `CheckoutLineHandlerRegistry`를 통해 상품 테이블별 핸들러에 위임하는 방식으로 변경되었다.

현재 지원 흐름은 다음과 같다.

- `UNION_PRICE`: 기존 카드 상품 흐름 유지
- `MANUAL_PRODUCT`: 수동 상품 가격, 재고, 노출 상태 검증 및 주문 라인 생성
- `SUPPLIES`, `OTHER_PRODUCT`: 아직 미구현 또는 미지원 흐름

`OrderProduct`에는 `productTable`이 추가되어 `order_products.product_id`가 어느 상품 테이블의 내부 PK인지 구분할 수 있게 되었다. 이를 위한 DB 스크립트도 `backend/script/order_products_product_table.sql`에 추가되어 있다.

### 관리자 주문

관리자 주문 API가 추가되었다.

- 목록: `POST /api/admin/orders/list`
- 상세: `GET /api/admin/orders/detail/{id}`
- 주요 파일:
  - `backend/src/main/java/com/shop/admin/order/controller/AdminOrderController.java`
  - `backend/src/main/java/com/shop/admin/order/service/AdminOrderServiceImpl.java`
  - `backend/src/main/java/com/shop/order/repository/OrderInfoRepositoryImpl.java`

관리자 주문 목록은 기간, 상태, 페이지 조건을 받아 `OrderInfoRepositoryCustom` 기반 QueryDSL 조회를 수행한다. 상세 API는 `OrderInfoDto`와 주문 상품 목록을 포함하는 `AdminOrderDetailDto`를 반환하는 구조다.

주의할 점은 목록 조회에서 각 주문마다 `orderProductRepository.findByOrderInfoId()`를 호출하고 있어 N+1 쿼리 가능성이 있다는 점이다. 현재 터미널 로그에서도 주문 목록 조회 후 주문별 상품 조회 SQL이 반복되는 흐름이 확인된다.

### 수동 상품

수동 상품 백엔드 CRUD 기본 흐름이 추가되었다.

- `backend/src/main/java/com/shop/admin/product/controller/AdminManualProductController.java`
- `backend/src/main/java/com/shop/product/service/manualProduct/ManualProductServiceImpl.java`
- `backend/src/main/java/com/shop/product/repository/manualProduct/ManualProductRepository.java`
- `backend/src/main/java/com/shop/search/event/ManualProductChangeEvent.java`

수동 상품 생성, 수정, 삭제 시 `ManualProductChangeEvent`를 발행해 검색 맵 동기화가 일어나도록 구성되어 있다.

점검이 필요한 부분도 있다.

- 수동 상품 수정 시에는 `publicId`를 변경하지 않고 유지한다. 생성 시에만 `UlidGenerator`로 발급한다.
- 삭제는 물리 삭제가 아니라 `isDeleted=true`, `isVisible=false` 방식의 소프트 삭제다.
- 예외 처리는 일부 `RuntimeException` 중심이라 운영 전 도메인 예외 정리가 필요하다.

### 검색

`ProductSearchMap`은 수동 상품을 검색/장바구니/상품 그리드에 노출하기 위한 분기를 갖도록 확장되었다.

- `ProductSearchMapServiceImpl`
- `ProductSearchMapEventListener`
- `ProductItemDtoMapper`
- `ManualProductChangeEvent`

`MANUAL_PRODUCT`에 대한 DTO 매핑과 검색 맵 upsert 흐름이 추가되었다. 다만 `SUPPLIES`, `OTHER_PRODUCT`는 아직 미구현 경로로 남아 있다.

### 인증

인증 응답 구조가 정리되었다.

- `AuthResponseDto`가 `token`과 `user` 중심 구조로 변경
- `AuthUserDto` 신규 추가
- refresh cookie path를 `/` 기준으로 통일
- logout 시 과거 경로와 현재 경로 쿠키를 함께 만료
- 이메일 중복 에러 코드 추가

주의할 점은 백엔드 예외 코드, `.cursor/rules/apispec.mdc`, 프론트 i18n 키가 완전히 같은 체계인지 최종 확인이 필요하다는 점이다.
